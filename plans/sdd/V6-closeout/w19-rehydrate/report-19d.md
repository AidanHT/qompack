## impl:rehydrate: status `done`, head `e65ada8f7ae3beea383f5309673d2e1a5482a09c`

### Root cause

D61's free-text summary screen tried to UNDO every shell's quoting (bash $'...'/$"...", PowerShell $Env:/backticks, cmd carets, Unicode quotes/spaces, nested shells, regex-vs-path guesses). No "undo" is complete: the w19c round-3 verify found a path after any non-ASCII byte read as an outside POSIX path (in-project café/sub/x.txt and 文档/设计/说明.md were WITHHELD and poisoned the build), $'/home/u/x' leaked an outside path, and \?\? was over-withheld. D63 inverts the test: a free-text summary is SHOWN only when a WHITELIST proves every token safe; everything the whitelist cannot vouch for is withheld by default. This is complete-by-construction for privacy (a whitelisted name can only be transformed by a backslash escape / cmd caret / PowerShell backtick — and the caret and backtick are themselves rejected, leaving only the backslash, which the name screen reads two ways), at the cost of over-withholding quoted/variable/glob/redirect commands.

## fix:rehydrate:r1: status `done`, head `f708c6935cff803a383e04b2a3d521134cf36808`

### Root cause

D63's first implementation (round 1 of this seat) had two kinds of gap. First, it did not apply its own completeness argument everywhere. The name screen read a backslash both ways, but the path check read it only as a separator, so bash's `.\.` = `..` got through. A backslash that ends a token (an escaped space, or a line continuation the store collapsed) was treated as a separator, so it could join two whitelisted words into a denied name or into a sibling of the root. Second, D63(1) says to mark only unquoted occurrences of the root, but the implementation marked them inside double-quoted runs as well and never judged what follows the mark there. So `"<root> old/x.txt"`, one shell word naming a sibling, was shown wherever the run held no backslash (on Linux and macOS, and on Windows with a forward-slash root). There were smaller gaps of the same kind: path starts were looked for only at the token start, after `= : ,` and after a greedy short option; a `..` was checked only between separators, and not at all beside the root's mark; URL tokens were exempt from every check; and a cut path-named value was judged by its directory alone, so a cut ending `private/den` was shown and a cut value among several cost a host call. All of these are closed by making the whitelist stricter, or by applying both backslash readings to what it already admits. No shell modelling was added.

## What the gate does now (D63, ADR 0011 §23)

**Structured values** are still judged whole by the host (containment plus the host's rules, one judgement per path):
- a one-word summary;
- the single path-named value of a JSON preview;
- the path part of a summary that starts at the root.

Changes this round for structured values:
- A structured value's names are matched as whole names. The project's own `.env.example`, `.gitignore`, `.github/...` and `secrets_test.go` are shown. `.env.`, `.env:stream` and `deny.txt#L4` are withheld.
- When there are several path-named values, or a value the store's cut fell inside sits among them, the host is never asked.
- A cut value is judged by its directory (by the host only when it is the preview's single value) and by the prefix rule.
- A one-word http(s) URL is free text and costs no host call.

**Free text** costs no host judgement. It is shown only when all three checks pass:
- (a) Every token is safe.
  - Letters, marks and digits, plus `- _ . , : = @ + # /`.
  - `~` only inside a word.
  - `\` only before a character that is not another `\`. A backslash that ends a token, or a doubled backslash, makes the token unsafe.
  - Standalone operators `&& || | ; > >> 2>&1 2> < >&2 1>&2`.
  - Extension: whole null-device and standard-stream tokens (`/dev/null` and its redirects, `/dev/stdin|stdout|stderr`, cmd's `>nul`, `2>nul`).
  - Simple double-quoted runs. Extension: a backslash inside a run is allowed and judged per word.
  - http(s) URLs: plain characters plus `?`, and each part after `&` must be a plain token.
  - `%` is never safe.
- (b) No token names an absolute or escaping path, under either backslash reading.
  - Path starts are checked at the token start, after a short option's first letter or all of its letters, and after `= : , @`.
  - At each start, these are withheld: a leading `/` or `\`, `~`, a drive `X:`, and `file:`.
  - Any `..` that touches a token edge, a separator, a delimiter or the root's mark is withheld. This covers `<root>/a/../b`, `-coverprofile=../x` and cmd's glued `cd..`. Ranges like `HEAD~3..HEAD` and `...` are shown.
  - Inside a quoted run, the root followed by a space and a word that is not an operator is a sibling, so it is withheld.
- (c) The text names no rule literal and no withheld name where a name starts. A non-ASCII letter now continues a name, so `café.env` is not `.env`.

The root is held together as one unit only when it is followed by end of text, a space, `"`, `/`, or a `\` when the root's spelling itself uses backslashes. Followed by anything else it is judged as the path outside the project it is: `<root>,x`, `<root>:x`, `/q/proj\old` (= /q/projold to bash).

### Root cause

The D63 gate judged a structured value by literal containment (filepath.Clean) and literal `..` checks. A glob that respells a parent or a separator through a class, `?` or a leading dot got past both: `[.][.]`, `.[.]`, `?.` and `.*` respell `..`, and path.Match also lets `[/]` match `/`. Deleting outsideIn had removed the only check that read `file:` in a path-named value.

Two of round 1's own refinements went too far:
- The whole-name screen for structured values ignored that a literal taken from the start of a glob segment (`secret` for `./secret*`) refuses every name beginning with it.
- One-word values were screened against every withheld basename, outside paths included, even when the host had judged that exact path.

The drop-reason screen lost the root-marking that e65's protect() gave it. In a spaced root it therefore redacted every project path, and in a plain root it missed absolute withheld project paths and a sibling of the root that is a whole error-chain part. Separately, three characters D63(2) lists as safe expand in zsh or PowerShell: `=` at a word start, extended-glob `#`, and a whole `@name` splat.

- **minor** `internal/rehydrate/pathgate.go:1407-1412 (safeChars `#` arm), :1511-1522 (pathStarts)`: A token that starts with `#` is accepted as a comment, but no path start is placed after the `#`.
