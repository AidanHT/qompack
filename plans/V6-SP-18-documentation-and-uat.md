## Mission

Qompack's entire value proposition is that it replaces vibes with measurement (`Qompack.md` §1.3 RC-3: *"No distortion metric, no ceiling, no regression signal"*). A system built on that claim that ships without a written account of what it does, what it stores, what it cannot do, and how a human verifies it on their own machine would be committing the same sin one layer up. SP-18 is that account. It owns every user-facing word in the repository: the README a stranger reads in ninety seconds, the user guide that teaches the mental model of *surrounding* rather than *replacing* compaction, the troubleshooting guide that starts from `qompack config print --provenance` instead of from guesswork, the generated configuration reference that cannot drift from `config.Defaults()` because CI regenerates and diffs it, the honest limitations list reproduced verbatim from §12 and §9, the upstream issue set that says plainly which problems are Claude Code's rather than Qompack's, and the scripted acceptance guide a human runs against a real project with a pass/fail verdict per scenario.

This slice exists at wave 5, and merges after SP-17 within that wave, for one reason: **documentation of an artifact that does not yet ship is fiction.** Every command name, every MCP tool argument, every config key, every latency budget and every degradation banner described here is a real observable produced by a subplan that has already merged. The subplan therefore has an unusual discipline: almost nothing here is prose written from the design document alone. The configuration reference is *generated* from `config.Defaults()`. The command list is checked against the seven committed `plugin/commands/*.md` files. The Loud-message glossary is checked against the nine `contract.ID` constants, the nine failure rows of 00-ARCHITECTURE §12.3 and the §12.2 `sync → spool` transition. The install instructions are checked against the committed `plugin/.claude-plugin/plugin.json`. Prose that cannot be checked against a machine-readable source is quoted verbatim from `Qompack.md` and asserted byte-for-byte by a test. That is what makes this subplan a *build* rather than a *write-up*.

**Gap G7.2 is closed here, and closing it means stating it.** §9's traceability matrix gives G7.2 ("No cheap-model option") an empty "Closed by" cell and the residual **"Not closeable from a plugin"**. There is no code that can close it. ## Design context (verbatim from Qompack.md)

Everything quoted below is normative content this subplan must reproduce, render, or verify. Section citations are to `Qompack.md` v1.2 unless prefixed `ARCH`, which cites `plans/00-ARCHITECTURE.md`.

### §0 — the thesis (README lead, user-guide mental model)

> Claude Code's compaction system is a well-engineered three-tier pipeline whose core design decisions — deferring the expensive LLM call, reusing the conversation's own cache prefix for the summarization request, surgical `cache_edits` deletion — are correct and non-obvious. This plan does not propose replacing it. It proposes **surrounding it**.

> Claude Code's compaction treats context reduction as a *summarization problem under a token budget*, when it is actually a *rate–distortion problem under a prefix-cache cost model*, and almost every observed failure is a consequence of optimizing the wrong objective with the wrong cost function and no measurement loop.

> **Name rationale.** *Qompack* is a phonetic play on "compact" — same sound, distinct and searchable spelling, unclaimed as a package/command name. The guiding design principle behind it is that of a palimpsest: a manuscript overwritten with new text where the earlier writing remains legible underneath.

### §7.1 — the fundamental constraint (user-guide mental model, cannot-do lead)

> **A plugin cannot replace Claude Code's compaction. It can only surround it.**
>
> This is the single most important design constraint and it shapes everything below. Qompack is a *sidecar*: it observes via hooks, maintains external durable state, and re-injects via `additionalContext`. It never intercepts the summarizer, never modifies the message array directly, and never assumes it can prevent a compaction from happening.
>
> Everything is designed to degrade gracefully. If a hook stops firing, Qompack becomes a passive recorder and the session behaves exactly as it does today.

### §7.3 — hook surface (user guide, "what changes in a session")

| Hook | Layer | Responsibility |
|---|---|---|
| `PostToolUse` | L0 | Chunk and store tool results; update DAG, sketches, Sequitur; detect redundancy |
| `UserPromptSubmit` | L0 | Capture user intent **verbatim and immutably** (closes G2.3); update BOCD features |
| `SessionStart` | L0/L5 | Branch on `source`: `startup`/`resume` → load store; `compact` → rehydrate |
| `PreCompact` | L4 | Write immutable checkpoint; emit focus instructions via `custom_instructions` |
| `PostToolUse` (todo/git) | L3 | Task-boundary signals for the scheduler |
| `Stop` / `SubagentStop` | L0 | Capture subagent detail before it is double-compressed (closes G10.1) |
| `SessionEnd` | L1 | Flush, compact the store, write session index |

### §8.7 — the eight MCP tools (user-guide reference section)

| Tool | Signature | Purpose |
|---|---|---|
| `recall` | `(query, k=5)` → hits | Search the store by content, path, or symbol; returns hashes and summaries |
| `expand` | `(hash \| tool_use_id)` → content | Re-materialize a cleared tool result |
| `re_read` | `(path, at=null)` → content | Current or historical version of a file |
| `already_tried` | `(target, approach)` → bool + reason | Bloom membership plus the stored reason when present |
| `record_eliminated` | `(target, approach, reason)` | Write negative knowledge |
| `timeline` | `(from, to)` → segments | What happened between two points |
| `why` | `(decision_id)` → rationale | Retrieve a decision and its evidence |
| `dropped` | `()` → list | What is currently out of context |

> **Design note:** `already_tried` should be surfaced in the rehydrated context as a *standing instruction*, not merely an available tool. "Before committing to an approach, call `already_tried`." Otherwise the affordance exists and goes unused.

> - Every retrieval result is tagged ephemeral at birth and becomes the **first** eviction candidate, ahead of ordinary tool results, in the plugin's droppable-block ranking (§8.4).
> - Retrieval tools return the **minimum sufficient span** by default — the matching function or hunk, not the file — with an explicit `full=true` escape hatch. Most post-compaction questions are "what did that one function look like," not "give me the file."
> - Repeated expansion of the same hash within a session is a signal, not a cost: the Analyzer promotes frequently-re-expanded content into the next checkpoint's pointer tier with a higher slice weight.

### §8.3 — eliminations: sources, descriptor, staleness, three-way answer, scope

> Sources, in descending reliability:
>
> 1. Explicit agent declaration via the MCP tool `record_eliminated(target, approach, reason)`
> 2. Slash command `/qompack:pin --eliminated`
> 3. Heuristic detection: a test-fail → revert → different-approach pattern in the DAG
> 4. Explicit user statements ("that didn't work," "we tried that")
>
> Canonical descriptor: `(normalized_path, symbol_or_null, approach_class, reason_hash)`. Insert into `tried.bloom`.

> **Staleness — negative knowledge must be able to expire.** An elimination is a *conditional* fact: "widening the pool timeout doesn't work **given pgbouncer 1.18**." Upgrade pgbouncer and the elimination is void — and a false `already_tried` that blocks a now-viable approach inverts the feature from asset to liability.
>
> 1. **The structured `eliminated[]` records are the source of truth; the Bloom filter is only a cache over them.**
> 2. Every elimination carries `depends_on`: the hashes of the files or configs the elimination's reason rests on (lockfiles, compose files, the file under test).
> 3. When a dependency hash changes, the elimination flips to `status: "stale"`. On the next idle window, `tried.bloom` is **rebuilt from active records only**.
> 4. `already_tried` responses distinguish the cases: *active* returns the reason; *stale* returns "previously eliminated, but the evidence has changed since — re-verification may be warranted," which is strictly more useful to the agent than either a block or silence.
> 5. `scope: "session" | "project"` controls cross-session carry-over: session-scoped eliminations ("this test is flaky today") die with the session; project-scoped ones ("this library fundamentally can't do X") persist and warm-start future sessions (§10 Phase 7).

### §8.5 — the standing focus-instruction template and the O1 span paragraph

> Encode what a competent engineer with no session history would get wrong. Do not restate file contents, directory structure, or command output — those are retrievable. Prioritise: intent, decisions and their rationale, approaches eliminated and why, and constraints discovered empirically.

> A durable checkpoint (`.qompack/checkpoints/0007.json`) fully covers the session through turn N, including all decisions, eliminations, and file state up to that point. Do not re-summarize that material. Summarize only what happened after turn N: new decisions, new eliminations, new intent, current work.

> Note what is **not** here: no code snippets. Files are pointers with a one-line reason.

### §8.6 — the eight-item rehydration order and the budget

> **Emits** via `hookSpecificOutput.additionalContext`, filled in importance order until the budget is reached:
>
> 1. **Invariants and pins** — verbatim, always
> 2. **Verbatim original user intent** — from L0, not from any summary (closes G2.3 permanently)
> 3. **Eliminated-approaches digest** — the top-N most relevant by slice score, plus a note that `already_tried()` covers the rest
> 4. **Decisions with rationale**
> 5. **Current work and next step**
> 6. **Pointers, not contents** — file paths with hashes and one-line reasons
> 7. **Drop report** — the explicit list of path-scoped rules, nested `CLAUDE.md` files, and truncated skills that are no longer in context (closes G4.5)
> 8. **Retrieval affordance notice** — one line telling the agent that `recall`, `re_read`, and `already_tried` exist

> **Instruction restoration (G4.1, G4.2, G4.4).** The rehydrator re-reads from disk, independently of Claude Code's own restoration:
>
> - Every `paths:`-scoped rule whose glob matches any file in the checkpoint's pointer set
> - Every nested `CLAUDE.md` in a directory containing a pointer-set file
> - A compact skill index (names and one-line descriptions only, ~450 tokens) so skill awareness returns

> **Budget discipline.** Default rehydration budget is deliberately far below Claude Code's 50K + 25K: target 8–12K.

### §8.2 — retention (user guide: budgets and retention)

> **Garbage collection.** Reference-counted, run on `SessionEnd`. Chunks unreferenced by any checkpoint, pin, or recent index entry beyond a retention window are collected. Default retention: 30 days or 10 sessions, whichever is longer.

### §11.1 / §11.2 / §11.3 / §11.4 — metrics explained (user guide status section, UAT criteria)

> **Fraction of Belady OPT.** For each compaction event in a logged session, compute the clairvoyant optimal keep-set under the same token budget, then score the policy's actual keep-set against it.

| Metric | Definition |
|---|---|
| First-divergence turn | Turns after compaction before compacted and uncompacted branches diverge |
| File-set Jaccard | Overlap of files touched over the next K turns |
| Redundant work rate | Re-reads of already-read files; re-attempts of eliminated approaches |
| Decision preservation | Fraction of pre-compaction decisions still correctly recalled |
| Rewrite tokens/session | Total `w · (n − p_min)` paid |
| Rehydration budget | Tokens spent restoring context |
| Retrieval hit rate | How often `expand`/`re_read` is called, and whether it prevented a re-read |
| **Compaction pause** | Wall-clock of the summarization call; target O(delta) under frontier advancement (O5) |
| **Residual span at compaction** | Tokens between frontier N and the compaction point — the direct driver of pause time |
| **First-turn-after latency** | Time to first token on the turn following compaction (captures rebuild + cache-write cost) |

> ### 11.3 Guardrails
>
> - Hook p99 latency < 15ms (L0), < 2s (L4)
> - Store growth sublinear in session length after dedup
> - No metric may regress by more than 2% to improve another without explicit sign-off
> - Every phase gate runs the full replay suite

> ### 11.4 Watch for
>
> - **Overfitting to replay.** Logged sessions were produced by an agent operating under the *current* system. Behaviour changes when the system changes. Re-collect sessions periodically under the new policy.
> - **Bloom false positives compounding.** At 1% they are safe; at 10% the agent starts skipping viable approaches. Monitor fill ratio and resize.

### §12 — risk register (troubleshooting sections must cover every row)

| Risk | Severity | Mitigation |
|---|---|---|
| **Undocumented hook contracts change** (G9.3): `SessionStart` `source=compact`, `additionalContext` reaching context, `PreCompact` timing | High | Contract monitor: assert each on every session start, log loudly and degrade to passive recording on failure. Never fail silently. |
| `PreCompact` timeout too short to write a checkpoint | Medium | Write incrementally on the scheduler's cadence so `PreCompact` only finalizes. Never depend on doing all the work in the hook. |
| Storage growth | Medium | Reference-counted GC, retention window, `/qompack:status` surfaces size |
| Hook latency on the hot path | Medium | Async queue-and-drain fallback; hard p99 budget |
| Rehydration crowds out working context | Medium | Hard budget cap; pointer-first design; measured in harness |
| Bloom saturation | Low | Monitor fill ratio; resize with a rebuild from `eliminated[]` in checkpoints |
| Plugin and Claude Code compaction fight each other | Medium | Soft floor well below the auto threshold; plugin acts first by design |
| Cache multipliers change | Low | Read `r` and `w` from config, never hardcode |
| **Stale negative knowledge blocks a now-viable approach** | High | Evidence-linked eliminations with `depends_on` hashes; Bloom rebuilt from active records on dependency change (§8.3). This risk is why the filter is a cache, never the source of truth. |
| Retrieval layer re-inflates the context window | Medium | Ephemeral-at-birth policy; minimum-sufficient-span defaults; retrieval results are first eviction candidates (§8.7) |
| Summarizer ignores the incremental-span instruction | Low | `custom_instructions` is advisory; the checkpoint remains authoritative and the rehydrator never depends on summary compliance (§8.5) |

### §12 — "What this plugin cannot do" (reproduced **verbatim** in `docs/cannot-do.md`)

> State these plainly rather than discovering them in month three:
>
> - **Cannot use a cheaper model for summarization** (G7.2). Upstream constraint.
> - **Cannot prevent a compaction** — only compact earlier and better.
> - **Cannot place or move `cache_control` breakpoints.** Claude Code manages its own cache markers, so the breakpoint-placement analysis in §5.6 is measurement-and-port material, not a plugin feature.
> - **Cannot access attention weights**, so H2O-style eviction stays out of reach; only perplexity proxies are available.
> - **Cannot force the `cache_edits` path** — where it is gated, the prefix constraint binds fully.
> - **Cannot change PTL retry, the circuit breaker, or the blocking-limit cliff.** It can only keep sessions away from those regions.
> - **Cannot modify the message array directly.** Everything flows through `additionalContext`.
> - **Cannot guarantee the summarizer honours focus instructions** — span narrowing (§8.5) and snippet prohibition (G3.4) are advisory; the durable checkpoint is the backstop for both.

### Cache limits verified 2026-08-23 — an ADDITIVE section of `docs/cannot-do.md`, never an edit to the verbatim block

§12's eight bullets and §9's fifteen residual strings are reproduced byte-for-byte and this section
does not touch them: `TestCannotDoListVerbatim` and `TestCannotDoCoversResiduals` assert containment,
so a document that carries the verbatim block **plus** a clearly separated section still passes. The
separation is required, not stylistic — the verbatim block is `Qompack.md`'s text and stays as such.

These four went into `docs/cannot-do.md` under the heading **"Cache behaviour Qompack cannot see"**,
after the cache-regime research recorded in `V2-report.md` §19 established which cache signals the
hook surface does and does not carry. Each is a fact with a source, not an inference:

| Limit | Why | Source |
|---|---|---|
| Qompack cannot tell whether the session is on the five-minute or the one-hour cache TTL | Claude Code selects it from your authentication — one hour on a Claude subscription, five minutes on an API key or third-party provider — and no hook input carries the auth mode. Qompack reads `ENABLE_PROMPT_CACHING_1H`, `FORCE_PROMPT_CACHING_5M` and `DISABLE_PROMPT_CACHING*` from the environment when they are set; when none is set it reports a **range** rather than guessing, and `/qompack:status` shows `ttl_regime: unknown`. Setting one of those variables is the one-line way to sharpen every cache-timing decision Qompack makes | `code.claude.com/docs/en/prompt-caching`, *Cache lifetime* |
| Qompack cannot detect a mid-session **model** switch, which empties the cache instantly | `model` appears in hook input on `SessionStart` only, and the reference notes it is not guaranteed present even there. There is no `$CLAUDE_MODEL`. So the turn after `/model` looks warm to Qompack and is not | `code.claude.com/docs/en/hooks`; *Switching models* |
| Qompack cannot detect **fast mode** being turned on, which also empties the cache | `fast_mode` is carried in the status-line payload and in no hook input | *Turning on fast mode* |
| Qompack cannot see actual cache hit rates | `cache_read_input_tokens` and `cache_creation_input_tokens` reach a **status-line** command, and a plugin may ship only `subagentStatusLine`, not the main `statusLine`, which is a user or managed setting. So Qompack's cache model is inferred from event timing, never measured. `docs/user-guide.md` carries an **optional** status-line snippet a user may paste into their own settings to feed the daemon real numbers; it is opt-in by construction and Qompack works without it | `code.claude.com/docs/en/statusline`; `code.claude.com/docs/en/plugins-reference` |

**What Qompack *can* see, so the list reads as a boundary rather than a shrug.** A change of **effort
level** is part of the cache key and *is* observable — `effort.level` arrives on `PreToolUse`,
`PostToolUse`, `Stop` and `SubagentStop`, and `$CLAUDE_EFFORT` mirrors it — so Qompack treats an
effort switch as an immediate cold cache. That is the one instant invalidation it can act on, and
`docs/user-guide.md` says so next to this table, because a limitations list that omits the
neighbouring capability teaches the wrong mental model.

### ARCH §12.1 / §12.2 / §12.3 — degradation (troubleshooting glossary source)

> **On any `SevCritical` failure:** `Monitor.Degrade` is called. That means, in order: `logging.Loud` (log file + `LOUD.log` + `systemMessage` on the next hook that may emit one), persist the reason to `state/contract.json`, set `Mode = ModeDegradedPassive`, and record it in `obs`. `/qompack:status` leads with a banner naming the failed assertion, what was expected, and what was observed. **Nothing fails silently — that is the whole point of the mechanism.**

> `ModeDegradedPassive` behaviour: L0 and L1 keep running (observe, chunk, store, sketches, DAG, verbatim capture, elimination records — the store stays correct and the session's data is not lost). Everything that *acts* is off: no `additionalContext` injection, no `customInstructions`, no scheduler-initiated checkpoints, no drop report. MCP retrieval tools stay available, because they are pull-based and cannot make anything worse.

> Recovery: assertions re-run every `SessionStart`. Two consecutive clean runs call `Monitor.Restore`, logged just as loudly as the degradation.

> `sync` → `spool` submode transition on 3 consecutive breach windows; logged at WARN; visible in `/qompack:status`; automatically reverts after 3 clean windows in a subsequent session. Under `spool`, the client never connects: it appends and exits, and the daemon drains on its idle tick. Data is not lost; only freshness is.

The **nine** §12.3 failure rows the Loud glossary must cover — `daemon unreachable`, `spool write fails`, `store corrupt (bad CRC, truncated object)`, `checkpoint MANIFEST mismatch`, `bloom load fails`, `config invalid`, `MCP tool panic`, `any hook panic`, `PreCompact about to exceed its timeout` — **plus the `sync → spool` transition of §12.2**, which is a submode change rather than a §12.3 row and is counted separately everywhere in this plan. ARCH §12.3's table has nine rows and SP-17 ships nine `TestDegradation_*` tests against them; a glossary claiming a tenth §12.3 row is claiming a row that does not exist.

The nine `contract.ID` constants the glossary must cover (ARCH §5.19): `session_start.fires`, `session_start.source_compact`, `hook.additional_context_delivered`, `precompact.has_time_to_write`, `precompact.custom_instructions_accepted`, `hook.payload_shape`, `mcp.server_registered`, `transcript.readable`, `plugin.root_resolves`.

## Implementation spec

### 1. `tools/devtool/configdocs/meta.go` — the per-key metadata table

Package `configdocs`. Imports `github.com/qompack/qompack/internal/config` only. Contains **no numeric literals** (every default comes from `config.Defaults()` at runtime), so the `nomagic` pass cannot fire.

**`Meta` has one entry per leaf of `config.Defaults()`, and this plan fixes no count.** Write the table by *generating* it, not by transcribing the enumeration below: on the branch you cut, run the walk described in §2 over `config.Defaults()`, take the dotted keys it yields in order, and give each one a row. Then reconcile against the enumeration below — every key it lists must appear, and any key the walk yields that it does not list is a leaf a wave-2-to-5 subplan added after this plan was written and gets a row with `GoType` from its Go kind, `Range` from the matching clause of `config.Validate()` (or from the `rng:`/`enum:` struct tag), and `Section` naming the architecture section that motivated it. The reverse — a listed key the walk no longer yields — is a `Meta` orphan and is deleted. `Leaves` reports both directions as errors and `TestConfigReferenceCoversEveryKey` fails on either, so the reconciliation is mechanical rather than a judgement call.

No number in this section is a gate. **Waves 2–5 each added leaves, and the two later waves will add more**; a plan that hardcodes a leaf count ships a test that fails the day the next key lands. The only assertions that gate CI compare `len(Meta)` against the walked leaf set and the rendered `NN keys.` line against `len(leaves)` — never against a literal.

### 2. `tools/devtool/configdocs/generate.go` — the renderer

```go
func Leaves(cfg config.Config) ([]Leaf, error)
func Generate(cfg config.Config) ([]byte, error)
```

**Walk order — normative, because map iteration is random and the output is diffed by CI.** `Leaves` reflects over `config.Config` using `reflect.TypeOf`, iterating **struct fields in declaration order**, recursing into struct fields, and stopping at any field whose kind is not `reflect.Struct` (or is a `*float64`, which is a leaf). The dotted key is the concatenation of the fields' `json` tag names (tag name before the first comma) joined with `.`. The top-level field's json name is the `Section`. Slices (`[]string`) are leaves, not recursion points. A field tagged `json:"-"` is **skipped and is not a leaf** — `config.SelectionCfg.Submodular.Enabled` is the one such field today, derived at `Load` time from `runtime.selection.submodularEnabled`, and rendering it would print a dotted path that `--set` cannot address.

**Value rendering.** `json.Marshal(leafValue)` verbatim, wrapped in backticks: `1024`, `"zstd"`, `["timestamps","ansi","pids","addresses","tmpPaths","durations"]`, `0.55`, `null`, `true`, `[]`. A `*float64` nil renders `null`. No re-formatting, no thousands separators — the rendered default must be pasteable into `.qompack/config.json`.

**Platform-dependent defaults render both values.** `config.Defaults()` returns one number per leaf — whichever one the *generating host* ships — but the page is generated once and committed, and the CI `docs` job re-renders it on ubuntu. A cell taken straight from `Defaults()` would therefore document only the platform it happened to be generated on, and `gen-config-docs --check` would report drift for any contributor who regenerated on Windows. `Generate` keeps a table, keyed by dotted path, of the leaves whose built-in default differs by platform, and renders those cells from the exported constants instead:

```go
// One entry today; both values come from internal/config, so this table can drift from the
// defaults only by a NEW platform-dependent leaf being added and not listed here.
var platformDefaultCells = map[string]string{
    "runtime.daemon.connectDeadlineMs": fmt.Sprintf("`%d` (`%d` on Windows)",
        config.ConnectDeadlineMsPortable, config.ConnectDeadlineMsWindows),
}
```

The preamble carries the one-line rule so a reader knows how to read such a cell: *"A default that differs by platform names every value in its Default cell, portable one first."* `TestGenerateRendersPlatformDefaultBothWays` asserts that the `runtime.daemon.connectDeadlineMs` row names both constants whatever `runtime.GOOS` the test itself is running on — which is exactly the platform-independence CI depends on — and that no other leaf's Default cell differs from `json.Marshal` of its `Defaults()` value.

**Output layout, byte-for-byte.** Two generated-file comment lines, blank line, then:

**The number block: `0200`–`0211`, and why not `0001`–`0012`.** `docs/adr/` is not empty and never was. It already carries per-package decision records written by earlier subplans — `0002-replay-methodology.md`, `0003-replay-overfit-recollection.md`, `0007-dag-slices-are-scores-not-drop-decisions.md`, `0030-sketch-binary-format.md` — and every verification checkpoint adds one more (`0018-v6-release-verification.md` is V6's own, written at its §10 gate). Grepping `docs/adr/NNNN-*.md` across `plans/*.md` shows four further numbers in the low block already spoken for by other subplans: `0008-observer-l0.md`, `0009-negative-knowledge-bloom-as-cache.md`, `0011-rehydration-budget-and-item-order.md`, `0012-scheduler-l3.md`. Numbering the D1–D12 architecture ADRs `0001`–`0012` would collide with seven of them, and renumbering *those* would break four committed files plus every plan that cites them.

So the twelve architecture ADRs take the reserved **`0200` block**, which nothing in the repository and nothing in any plan uses: ADR number *n* records decision D(*n* − 199), i.e. `0200` → D1 through `0211` → D12. Per-package ADRs keep the low numbers they already have, and SP-18 neither reads, renames, nor indexes them (see the boundary rule below).

**Index boundary rule, stated so a future reader does not "fix" it.** `docs/adr/README.md` indexes the twelve `02NN` architecture ADRs and nothing else. The per-package and per-checkpoint ADRs in the low block exist on disk, are owned by the subplans that wrote them, are not in `OwnedDocs()`, and are deliberately not listed — indexing them would put SP-18's placeholder, whitespace and link checks over files another subplan regenerates. The index's H2 says so in one sentence, so the omission reads as a decision rather than an oversight. If `TestAdrIndexEntriesExist` ever fails because a sibling ADR was added to the index, the index is what is wrong.

Each ADR is `# ADR 02NN — <title>` (the `# ADR NNNN — ` form the committed ADRs already use), then `**Status:** Accepted`, then `**Date:** YYYY-MM-DD` — the ISO-8601 date on which commit 1 lands, identical across all twelve files so the set reads as one decision record and the shape test can match a fixed pattern. Then `## Context`, `## Decision`, `## Consequences` (with a `### Positive` and a `### Negative` list), then `## References` citing both the ARCH section and the `Qompack.md` section. The `## Decision` body names its decision ID (`D1` … `D12`) explicitly. Context and Decision are sourced from ARCH §1's rationale column and the cited section; Negative consequences are real, not decorative (e.g. 0201: two processes to reason about, a lock file to reclaim, and an idle-exit policy to tune; 0205: we own MCP protocol drift; 0206: five sketch implementations to keep correct and versioned; 0210: every new tunable costs a config key, a validation rule, a `nomagic` entry and a config-reference row).

## Subagent strategy

This subplan is **heavy** in volume (about 4,000 lines of prose across twenty-one documents — nine prose documents plus twelve ADRs — a generator, and eleven test files) but light in coupling: each document is an independent artifact whose contract is a test file that already exists. That makes it near-ideal for parallel subagents, provided the shared surfaces stay in the main session.

**Stays in the main session, never delegated:**

- `test/docs/harness.go` and `OwnedDocs()` — one writer only. Every subagent's tests import it; two agents editing it produces a merge conflict inside a single package.
- The commit sequence. Subagents produce *files*; the main session stages, runs the gate, and commits. The seven commits are strictly sequential and are made only by the main session.
- `.github/workflows/ci.yml` and `tools/devtool/genconfigdocs.go` — both are SP-01 files with a wave-5 sibling (SP-17) also in flight, and the second is where a careless edit silently disables the `--check` gate (§3).
- The commit-7 merge of `develop` into this branch, and the `docs/security.md` link it enables.
- The final read-through pass (commit 7's third checkbox).

**Parallel batch A — dispatched together after commit 1's harness exists** (they share no file):

| Subagent | Owns | Returns |
|---|---|---|
| **A1 — reference generator** | `tools/devtool/configdocs/{meta.go,generate.go,generate_test.go}` | the three files, plus the generated `docs/config-reference.md`, the `BenchmarkGenerate` ns/op figure, and **the list of leaf keys its walk found that the implementation spec's enumeration does not list** (later waves' additions) together with the `Range`/`Section` it assigned each. Must report any leaf key whose `Range` disagrees with `config.Validate()` rather than silently widening the doc. Does **not** touch `tools/devtool/genconfigdocs.go`; the re-pointing of §3 is the main session's. |
| **A2 — user guide** | `docs/user-guide.md`, `test/docs/user_guide_test.go` | the two files, plus a list of every verbatim quote it used with its `Qompack.md` line reference so the main session can spot-check |
| **A3 — troubleshooting** | `docs/troubleshooting.md`, `test/docs/troubleshooting_test.go` | the two files, plus the completed Loud glossary as a table so the main session can diff it against the nine contract IDs, the nine §12.3 rows and the §12.2 `sync → spool` transition |
| **A4 — limits and upstream** | `docs/cannot-do.md`, `docs/upstream-issues.md`, `.github/ISSUE_TEMPLATE/upstream-tracker.yml`, `test/docs/limits_test.go` (seven tests) | the four files, plus a byte-for-byte diff report of the twelve §12 bullets against `Qompack.md`. `docs/security.md` is SP-17's and is not A4's to write, read or assert. |
| **A5 — UAT** | `docs/uat.md`, `test/docs/uat_test.go` | the two files, plus the twelve-scenario threshold table so the main session can verify every number traces to a design-document or architecture value |

**Sequential, in the main session, before batch A:** commit 1's README, `docs/architecture.md`, the twelve ADRs, and their test files (`inventory`, `placeholders`, `links`, `readme`, `architecture`). These set the vocabulary (decision names, section titles, link targets) that every batch-A document links into, so writing them first prevents five agents inventing five different names for D2.

**Integration protocol.** Each subagent returns file *contents*, not commits. The main session writes the files, appends the new paths to `OwnedDocs()`, runs `go test ./test/docs/...`, and only then commits — in the commit order above, regardless of the order agents finished. If two agents quote the same `Qompack.md` passage with different whitespace, the main session normalizes to the source document's bytes; `RequireVerbatim` is whitespace-run-tolerant but the repository should still be consistent.

**Explicit anti-goal.** Do not parallelize *within* a document (one agent per section). Documents have a voice and a through-line; a five-agent user guide reads like five user guides.

## Exit criteria

### Qompack.md exit criteria applicable to this slice

SP-18 ships no phase; it ships the guide by which a human confirms every shipped phase on their own machine. `docs/uat.md` therefore quotes and operationalizes these verbatim, and the corresponding UAT scenario must be executable as written:

> **Phase 1 — Exit criterion:** store size vs. raw transcript ratio ≥ 4:1 on read-heavy sessions (measure with and without canonicalization — the gap on test-output-heavy sessions justifies O2 on its own); hook p99 < 15ms.

> **Phase 2 — Exit criterion:** measurable reduction in repeated-elimination events in replay, with zero stale-block incidents (a viable approach wrongly refused) on sessions that include a dependency change.

> **Phase 3 — Exit criterion:** post-compaction first-divergence turn index improves against Phase 0 baseline at a *smaller* rehydration budget than stock; measured reduction in summarization-call input tokens when the span instruction is honoured.

> **Phase 4 — Exit criterion:** measured reduction in total rewrite tokens per session, with no regression in divergence metrics; median compaction pause and residual span flat as session length grows (the amortization claim, tested directly).

And the §11.3 guardrails, rendered as a table in `docs/user-guide.md` and as thresholds in `docs/uat.md`:

> - Hook p99 latency < 15ms (L0), < 2s (L4)
> - Store growth sublinear in session length after dedup
> - No metric may regress by more than 2% to improve another without explicit sign-off
> - Every phase gate runs the full replay suite
